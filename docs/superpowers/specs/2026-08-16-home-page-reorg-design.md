# Дизайн: реорганизация стартовой страницы (ОБЗОР) + AEO-фундамент

> Составлен: 2026-08-16 · Статус: черновик, ждёт подтверждения пользователя

## Контекст и цель

Пользователь: текущая вкладка ОБЗОР неинформативна для случайного посетителя — статус-бар, график цены, 4 плотных текстовых карточки нарративов (всегда полностью развёрнутых), сентимент-бар, фаза цикла, таблица последних блоков. Нет точки входа/крючка, нет объяснения что такое сайт, нет приглашения исследовать глубже.

Дополнительное требование: учесть 15-пунктовый чек-лист AEO/GEO (как попасть в рекомендации ChatGPT/Perplexity/Gemini). Разобрано отдельно — большинство пунктов (подборки, vc.ru/Habr, YouTube, Reddit, LinkedIn/TenChat, упоминания бренда) не код, это задача пользователя вне репозитория. Применимо в коде: `robots.txt`, `sitemap.xml`, Schema.org, чёткое определение сайта первым предложением, и — самое существенное — **весь контент сайта рендерится JS, в исходном HTML пусто**. Краулер без исполнения JS не увидит ни одного нарратива.

Утверждено (брейнсторм, визуальные макеты через companion): направление **A + C** — редакционный крючок (главная история как заголовок) плюс плитки-порталы в разделы сайта, скомбинированные в одну страницу.

## Часть 1 — Новая структура вкладки ОБЗОР

### Порядок блоков (сверху вниз)

1. **Определение сайта** — одно предложение, статично, не генерируется: «Bitcoin Intel — платформа нарративного анализа Bitcoin: сталкивает противоречивые сигналы рынка и институтов, показывает где правда ещё не решена.»
2. **Главная история** — топ-1 нарратив по `score.total` (та же сортировка, что уже использует `renderDashStatus()`), показан **полностью** — весь текущий формат карточки нарратива (tension/macro/takeaway/alt-scenario/pos-neg-neu/score), не сокращённый
3. **Ещё нарративы** — оставшиеся нарративы (2-4 шт., сколько прошло порог `SCORE_MIN` минус уже показанный топ-1) в виде **свёрнутых строк**: точка-индикатор направления, название кластера, счётчик сигналов · score, стрелка. Клик по строке → `pendingScrollSignal`-подобный переход в ДАЙДЖЕСТ с фильтром по кластеру (переиспользует существующий `data-cl`-обработчик, не новая логика). Под списком — «ВСЕ СИГНАЛЫ → ДАЙДЖЕСТ» (как сейчас в блоке «Общий фон»). **Пустой случай:** если ни один нарратив не прошёл `SCORE_MIN` (`active.length === 0`), текущий код показывает единственный «слабый» нарратив (`weak:true`) вместо списка — в новой структуре это означает «Главная история» есть (с бейджем СЛАБЫЙ СИГНАЛ, как сейчас), а секция «Ещё нарративы» просто не рендерится (0 строк) — не пустой блок с заголовком, весь `<div class="bi-section-label">` тоже скрывается, не только список под ним
4. **Исследовать глубже** — 4 плитки-портала на реальные кластеры навигации (`CLUSTERS` в `js/app-main.js`): 📡 LIVE (цена/дайджест/метрики/пулы), ⚙️ ECOSYSTEM (технологии/Lightning/инструменты), 📖 FUNDAMENTAL (теория/макро/Saylor Series), 🔬 ANALYSIS (анализатор/холдеры/все нарративы). Клик → `selectCluster(key)`, уже существующая функция, без новой маршрутизации
5. **Тикер живых данных** — компактная строка: цена BTC/USD, фаза цикла, счётчик сигналов (🟢/🔴). Замена текущих отдельных блоков «Фаза цикла» (крупная панель) и статус-бара — то же самое, сжатое в одну строку

### Что убирается с первого экрана (не с сайта — переносится, не дублируется)

**Исправлено после сверки с кодом (первая версия дизайна ошибочно предполагала дублирование — его нет, grep подтвердил: `dash-cycle`/`price-chart-wrap`/`blocks-list` существуют РОВНО один раз в `index.html`, только на ОБЗОРЕ):**

- Полноразмерный график BTC/USD (`#price-chart-wrap`) + ссылка «Себестоимость и Realized Price → МЕТРИКИ» → **физически переносятся** (не копируются) в `tab-analytics` (МЕТРИКИ) — тематически туда и просились
- Полноразмерная панель «Фаза цикла» (`.dash-cycle`) → сжимается в тикер на ОБЗОРЕ (той же информацией — см. ниже), полная панель **переносится** в `tab-analytics` (МЕТРИКИ)
- Таблица «Последние блоки» (`#latest-blocks-panel`) → **переносится** в `tab-pools` (ПУЛЫ), рядом с уже существующими `#pool-summary`/`#pool-detail` — тематически то же самое (блоки/пулы)
- JS-код, пишущий в эти элементы (`renderBlocks()`, `initPriceChart()`, `calcCyclePhase()`), уже null-safe (`if (list)`, `if (title)` и т.п.) — перенос HTML между вкладками не требует правок в этих функциях, только правки `triggerTabData()` (что́ инициализировать при открытии какой вкладки)
- Статус-бар (`#dash-status-bar`) — не переносится и не удаляется, **становится тикером**: те же id (`dash-status-phase`, `dash-status-ratio`, `dash-status-pos/neg/neu`), только компактнее визуально + один новый элемент `#dash-status-price` (текущая цена, из уже существующей `dashBtcPrice`), обновляется в существующей `renderDashStatus()`

### Технически: что меняется, что нет

**Исправлено:** нарративы рендерит `renderDashboard()` (js/app-main.js, не `renderDashStatus()` — отдельная, меньшая функция только для статус-бара/топ-3, вызывается из конца `renderDashboard()`).

- `renderDashboard()` — рефакторинг рендера: сортировка/отбор нарративов (`scored`/`active`/`shown`, `SCORE_MIN`, `SCORE_HOT`) не меняется; меняется ТОЛЬКО цикл `shown.forEach(...)`, который сейчас строит ВСЕ элементы через `renderNarrativeItem()` — первый (`idx === 0`) остаётся через `renderNarrativeItem()` без изменений, остальные — через новую компактную функцию `renderNarrativeMiniRow(key, cl, score)`, добавляются в отдельный контейнер `#dash-narratives-mini-list`, не в `#dash-narratives-list`
- Клик по мини-строке переиспользует уже существующий `goToDigest(clusterKey)` (js/app-main.js) — та же функция, что уже вызывает клик по «СМОТРЕТЬ В ДАЙДЖЕСТЕ» на полной карточке, отдельной функции не нужно
- Новая функция `renderExploreTiles()` — статичный HTML (4 плитки), переиспользует CSS-классы `.toc-card-grid`/`.toc-card`/`.toc-card-title`/`.toc-card-subtitle` (уже существуют, добавлены в этой же сессии для карточного оглавления ТЕОРИИ) — не новый визуальный язык
- `selectCluster(key)` — не меняется, только новый вызывающий код (плитки)
- HTML `index.html` — блоки перемещаются между вкладками (см. раздел выше), не удаляются

### 2.2 `sitemap.xml` (новый файл, корень репозитория)

Сайт — SPA без реальных отдельных URL на вкладку (переключение через JS-состояние, не роутинг/хеши) — содержательный sitemap с несколькими `<url>` невозможен без изменения архитектуры навигации (вне объёма этой сессии). Минимальный честный sitemap — одна запись на корень:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://alxcheh.github.io/Bitcoin-Intel/</loc>
    <changefreq>hourly</changefreq>
  </url>
</urlset>
```

### 2.3 Schema.org JSON-LD (в `<head>` `index.html`)

`WebSite`, не `Organization` — сайт не оформлен как юрлицо/бизнес, `Organization` было бы нечестной заявкой. Статичный блок, не генерируется:

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "name": "Bitcoin Intel",
  "url": "https://alxcheh.github.io/Bitcoin-Intel/",
  "description": "Платформа нарративного анализа Bitcoin: сталкивает противоречивые сигналы рынка и институтов, показывает где правда ещё не решена.",
  "inLanguage": "ru"
}
</script>
```

### 2.4 Статический снимок нарративов для краулеров (главное изменение)

**Проблема:** `dash-narratives-list` (и весь остальной контент сайта) — пустой `<div>` до `fetch()` + JS-рендера. Краулер без исполнения JS видит ничего.

**Решение:** новый скрипт `scripts/prerender_home.py`, встроенный в существующий `synthesize` job workflow `deploy.yml` — **сразу после** шага `Run synthesizer` (`data/synthesis_cache.json` уже свежий на этот момент). Скрипт:
1. Читает `data/synthesis_cache.json` + `signals.json`
2. Тем же порядком отбора, что `renderDashStatus()` (топ по `score.total`, порог `SCORE_MIN`), строит статический HTML — главную историю и мини-строки
3. Записывает результат между HTML-маркерами в `index.html` (`<!-- PRERENDER:HOME:START -->` / `<!-- PRERENDER:HOME:END -->`) — тот же принцип regex-замены между маркерами, что уже использует `scripts/update_js_cache_bust.py` для `?v=hash`

**Почему не ломает текущее поведение:** `dash-narratives-list` как контейнер уже существует, JS (`renderDashStatus()`) уже делает `el.innerHTML = ...` при каждой загрузке — просто теперь контейнер не пустой ДО этого момента, а с прогруженным на билде снимком. Обычный браузер с JS увидит его на долю секунды до перерисовки живыми данными (тот же эффект, что сейчас даёт "loading..." — не хуже), краулер без JS увидит финальный текст.

**Коммитится в тот же sync-PR**, что и `data/synthesis_cache.json` (шаг `Commit synthesis cache via PR` в `deploy.yml` — добавить `git add index.html` туда же) — снимок никогда не расходится с реальным состоянием синтеза, обновляется автоматически при каждом content-значимом изменении, без ручной синхронизации.

**Объём снимка (сознательно ограничен):** только «Главная история» + «Ещё нарративы» (текстовый контент, ради которого краулер сюда приходит). График цены, тикер, плитки-порталы — не пререндерятся: цена требует live API (не в юрисдикции этого скрипта), плитки статичны и не несут уникальной информации без контекста.

## Тестирование

- `renderDashStatus()`: топ-1 идёт через существующий полный рендер без регрессии (уже покрыто существующими тестами блока нарративов, если есть — проверить), остальные — новый тест на `renderNarrativeMiniRow()` (структура строки, клик ведёт на правильный `data-cl`)
- `renderExploreTiles()`: 4 плитки, каждая с корректным `onclick="selectCluster('...')"`, ключи совпадают с реальными `CLUSTERS`
- `scripts/prerender_home.py`: golden-тест на реальных `data/synthesis_cache.json`/`signals.json` — снимок содержит текст топ-1 нарратива; тест на маркеры (существуют ровно одна пара `PRERENDER:HOME:START/END` в `index.html`, замена идемпотентна — повторный прогон не дублирует контент)
- `robots.txt`/`sitemap.xml`: простая проверка валидности (parseable XML, непустой robots.txt содержит ожидаемые User-agent записи)

## Объём этой сессии

Часть 1 (редизайн ОБЗОРА) и Часть 2 (AEO-фундамент) реализуются вместе, по решению пользователя. `sitemap.xml` — минимальная честная версия (SPA без реального роутинга), расширение до многостраничного sitemap — future work, не блокирует эту сессию.
