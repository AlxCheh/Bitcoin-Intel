# Дизайн: раздел «Saylor Series» внутри вкладки ТЕОРИЯ

> Составлен: 2026-08-16 · Статус: черновик, ждёт подтверждения пользователя

## Контекст и цель

Пользователь обрабатывает подкаст-серию Роберта Бридлава «What is Money?» с Майклом Сэйлором (17 эпизодов, ~25 часов, премьеры с 2020-11-20) и хочет разместить на сайте разбор каждого эпизода — глубже текущего формата THEORY_ESSAYS.json (один сжатый пункт аккордеона), с максимумом связей: с другими панелями ТЕОРИИ, с сигналами (`signals.json`), с сущностями (`ENTITIES.json`), и между эпизодами самой серии.

Первый эпизод уже записан как эссе `breedlove-saylor-2020-rise-of-man` в `THEORY_ESSAYS.json` (panel `theory-money`, icon 07) — эта запись будет удалена и заменена полноценным разбором по новой архитектуре.

Утверждённый подход (из брейнсторма): **вариант C** — мини-раздел внутри вкладки ТЕОРИЯ, а не отдельная вкладка верхнего уровня и не 17 отдельных строк в `theory-toc`. Одна строка в `theory-toc` → индекс-карточки эпизодов → полноценная детальная панель на эпизод.

## Архитектурное решение: данные живут в THEORY_TOPICS.json

Ключевая находка при разборе: обратный рендер связей уже реализован, но **жёстко зашит на конкретный JS-массив**:

- `theory_refs` на сущности (`js/app-main.js:1278`) — `(THEORY_TOPICS || []).find(x => x.id === tid)`
- `signal_refs` на топике — та же логика поиска топика по id в `THEORY_TOPICS`
- Кросслинк `{type:"entity", entity_id, text, label}` внутри `items[].crosslinks[]` — уже поддержан `renderAccItem()`, работает для любого топика без правок

Если эпизоды хранить в **отдельном новом файле** (`SAYLOR_SERIES.json`), все три механизма придётся раздваивать (проверять два массива вместо одного) — лишний код и лишняя площадь для рассинхронизации.

**Решение: эпизоды — это записи в `THEORY_TOPICS.json.topics[]`**, той же формы, что `theory-dice-seed`/`theory-quantum` (`id`, `panel_title`, `panel_tag`, `intro`, `items[]`, `source_footer`, опционально `signal_refs`). Это даёт бесплатно: связь с сущностями, связь с сигналами, связь с другими панелями ТЕОРИИ (через `items[].crosslinks[]` с `target_panel`) — все три из четырёх запрошенных типов связей работают без единой строки нового кода в этих механизмах.

### Проблема, которую это создаёт, и её решение

Generic-сканер `renderTheoryTopics()` (`js/app-main.js:762`) для каждого топика без явного `id="{id}-mount"` в разметке кидает его в общий контейнер `theory-topics-container`, который физически лежит во вкладке **MACROCONTEXT** — 17 эпизодов без мест монтирования утекли бы не на ту вкладку. Хардкодить 17 mount-div'ов в `index.html` противоречит смыслу THEORY_TOPICS.json («без правки index.html»).

**Фикс:** новое поле `target_group: "saylor-series"` на топике-эпизоде (аддитивное, не ломает ничего существующего — неизвестное поле просто игнорируется). `renderTheoryTopics()` получает один явный пропуск: топики с `target_group` не идут ни в точечный mount, ни в общий контейнер — они целиком в ведении отдельной функции `renderSaylorSeriesSection()`.

Эта функция:
1. Фильтрует `THEORY_TOPICS` по `target_group === 'saylor-series'`
2. Рендерит карточку-индекс (номер эпизода, заголовок, дата, тизер) в единственную статичную точку монтирования `<div id="theory-saylor-series-mount"></div>` в `index.html` (внутри вкладки ТЕОРИЯ, среди остальных мест монтирования — `theory-dice-seed-mount` и т.п.)
3. Для каждого эпизода рендерит полную панель **тем же `renderTheoryTopic()`**, что и для `theory-dice-seed` — ноль дублирования кода для самого разбора
4. Клик по карточке в индексе — `scrollIntoView()` на панель эпизода (тот же паттерн, что у `uncollapseAndScrollTo()`)

### TOC

Одна новая строка в `renderTOC('theory-toc', [...])`:
```js
{ target: 'theory-saylor-series-mount', title: 'Saylor Series', subtitle: 'Роберт Бридлав и Майкл Сэйлор — 17 эпизодов о деньгах и цивилизации' }
```

## Формат содержания эпизода

Черновик пользователя для эпизода 1 (полнотекстовая статья: H1, интро-абзац, H2-секции с прозой, список, секция «При чём тут Биткоин», футер-цитата) **укладывается в существующую форму топика без структурных изменений**:

| Часть статьи пользователя | Поле THEORY_TOPICS.json |
|---|---|
| H1 + интро-абзац | `panel_title` + `intro` |
| Каждая H2-секция (Огонь, Праща, Вода, Рим, Крах протокола, Боль как сигнал, При чём тут Биткоин) | Один `items[]` — `icon`, `label` = заголовок секции, `paragraphs[]` = проза секции |
| Список внутри «Рим» | **Решено (после ревью плана пользователем):** `renderAccItem()` расширен — элемент `paragraphs` может быть либо строкой (как раньше), либо `{ list: [...] }`, рендерится как `<ul><li>`. Список сохраняется дословно, не превращается в один абзац через точку с запятой |
| Итоговая мысль секции (если есть) | `highlight` |
| Кросслинки на другие панели ТЕОРИИ / сущности / сигналы | `items[].crosslinks[]`, `signal_refs` на топике |
| Футер-цитата с источником и ссылкой на перевод | `source_footer` |

Отличие от текущих топиков (`theory-dice-seed` и т.п.) — не в форме, а в **глубине текста внутри `paragraphs`**: полноценная развёрнутая проза вместо 1-2 сжатых абзацев на пункт. Формат это уже допускает (нет ограничения по длине), проверка нужна только визуально (не станет ли аккордеон-пункт неудобно длинным при раскрытии — решается на глаз при первой реализации).

## Связи между эпизодами (`related_episodes`)

Новое поле на топике-эпизоде: `related_episodes: ["saylor-series-02", ...]` — те же критерии, что `context_chain` у сигналов (Шаг 5 алгоритма CLAUDE.md): без понимания эпизода X текущий эпизод теряет часть смысла. **Не заполняется для эпизода 1** — заполнять только когда появится реальный эпизод 2 (тот же принцип, что подтверждён для сигналов и Golden Dataset: связь — на честном тесте по факту существования обеих сторон, не наперёд). Рендер — отдельный блок в конце панели эпизода, аналогичный по виду `crosslinks`, но со `scrollIntoView` на панель другого эпизода вместо панели ТЕОРИИ.

## Идентификаторы эпизодов

`id: "saylor-series-{NN}"` (`saylor-series-01`, `saylor-series-02`, ...) — двузначный номер с ведущим нулём для сортировки строк, не зависит от даты премьеры (в отличие от `id` сигналов).
