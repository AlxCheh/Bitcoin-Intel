# Дизайн: карточное оглавление ТЕОРИИ + Saylor Series как под-хаб

> Составлен: 2026-08-16 · Статус: черновик, ждёт подтверждения пользователя

## Контекст и цель

Пользователь: вкладку ТЕОРИЯ стало тяжело читать — плоский список из 9 строк оглавления вперемешку (деньги, сеть, governance, DCA, passphrase, hashrate, dice-seed, quantum, Saylor Series), без группировки по смыслу, и `Saylor Series` в перспективе (17 эпизодов) станет неудобной простынёй на одной длинной странице.

Согласованный подход (брейнсторм): карточная сетка вместо списка строк + группировка по смыслу для ТЕОРИИ + `Saylor Series` переводится на модель «сетка карточек-эпизодов → клик показывает ровно один эпизод». Остальные 8 панелей ТЕОРИИ поведение не меняют — по-прежнему все на одной длинной странице, меняется только форма самого оглавления.

## Часть 1 — Карточная сетка `renderTOC()`

### Почему не создавать отдельную функцию для ТЕОРИИ

`renderTOC()` — единственная, документированная в самом коде точка рендера оглавления для **трёх** вкладок (`theory-toc`, `macrocontext-toc`, `lightning-toc`, `theory-toc` из этой же функции). Комментарий над функцией: «Единственное место, где эта разметка теперь пишется — не копировать inline-стилями в новые вкладки». Форкать под ТЕОРИЮ отдельную копию — прямое нарушение этого правила.

### Обратная совместимость через форму входных данных

`renderTOC(containerId, items)` сейчас принимает плоский `items: [{target, title, subtitle}]`. Меняется так, чтобы старые вызовы (`macrocontext-toc`, `lightning-toc`) остались рабочими без правок:

```js
// Старый вызов — работает как раньше, просто ряды карточек без заголовков групп:
renderTOC('macrocontext-toc', [{ target, title, subtitle }, ...]);

// Новый вызов — с группировкой (ТЕОРИЯ):
renderTOC('theory-toc', [
  { group: 'ОСНОВЫ', items: [{ target, title, subtitle }, ...] },
  { group: 'БЕЗОПАСНОСТЬ', items: [...] },
  { group: 'МЕДИА', items: [...] }
]);
```

Определение формы — по наличию `items[0].group !== undefined` (первый элемент — группа) vs `items[0].target !== undefined` (первый элемент — плоская запись). Функция сама приводит плоский массив к одной безымянной группе внутри, дальше рендер один и тот же путь — не два параллельных куска кода.

### Визуал

Замена `flex-direction:column` (список строк) на CSS grid, `repeat(auto-fill, minmax(220px, 1fr))` — адаптивная сетка 2-4 колонки по ширине экрана. Каждая карточка сохраняет те же визуальные токены, что и текущая строка (`font-family:var(--serif)` italic для заголовка, `var(--dim)` для подзаголовка, номер `var(--mono)` `var(--btc)`) — не новый визуальный язык, тот же самый, только в форме плитки: `border:1px solid var(--line)`, `hover: border-color var(--btc)` (тот же hover-паттерн, что `.crosslink`/`.ep-fn-badge`).

Заголовок группы — `font-family:var(--mono);font-size:10px;color:var(--btc);letter-spacing` — тот же стиль, что `.panel-tag`/лейблы бейджей, не новый.

Счётчик «📑 СОДЕРЖАНИЕ · N» в шапке остаётся — N считается по сумме `items.length` всех групп (для сгруппированного вызова) или `items.length` напрямую (для плоского) — уже видимое сейчас поведение, не меняется.

### Группировка ТЕОРИИ (согласовано)

| Группа | Панели |
|---|---|
| ОСНОВЫ | Что такое деньги · Семь сетевых эффектов · Bitcoin Governance · Стратегия DCA · Хешрейт и сложность: единицы измерения |
| БЕЗОПАСНОСТЬ | Насколько надёжна ваша парольная фраза? · Сид на костях · Квантовая угроза |
| МЕДИА | Saylor Series |

`macrocontext-toc`/`lightning-toc` остаются плоскими вызовами — своя короткая (4-5 строк) TOC не нуждается в группировке, менять их данные не нужно, только автоматически получают новый визуал сетки вместо списка.

## Часть 2 — Saylor Series как под-хаб

### Текущее поведение (что меняется)

`renderSaylorSeriesSection()` сейчас строит ОДНУ строку HTML: индекс-карточки + `episodes.map(renderTheoryTopic).join('')` — все существующие эпизоды через `el.innerHTML = html` целиком. При 17 эпизодах × ~9 пунктов аккордеона каждый — это очень длинная секция на одной странице, даже если сам `theory-toc` теперь ссылается на неё одной строкой.

### Новое поведение

1. По умолчанию (`renderSaylorSeriesSection()` без параметра / после `renderTheoryTopics()`) рендерится **только** сетка карточек-эпизодов внутри `theory-saylor-series-mount` — без единой полной панели эпизода в DOM.
2. Клик по карточке эпизода → вызывает `showSaylorEpisode(id)`: рендерит **ровно один** `renderTheoryTopic(episode)` в тот же контейнер, добавляет кнопку «← Ко всем эпизодам» сверху панели.
3. Клик «← Ко всем эпизодам» → `showSaylorSeriesIndex()`: снова рендерит только сетку карточек (переиспользует ту же функцию построения индекса, что и шаг 1 — не дублирует разметку).
4. `related_episodes`-бейджи (уже реализованы) при клике должны не просто `scrollIntoView`, а сначала гарантировать, что целевой эпизод отрендерен — если пользователь кликает бейдж на эпизоде 2, а эпизод 1 сейчас не в DOM (скрыт под индексом), нужно сначала вызвать `showSaylorEpisode('saylor-series-01')`, потом `scrollIntoView`. Это меняет `onclick` бейджа с прямого `document.getElementById(...).scrollIntoView(...)` на вызов новой функции `goToSaylorEpisode(id)`, которая делает и то и другое.

### Что не меняется

- Формат данных `THEORY_TOPICS.json` (топики эпизодов) — не трогается вообще.
- `renderTheoryTopic()` — не трогается, переиспользуется как есть для рендера одного эпизода.
- `related_episodes` badge-рендер (`.ep-fn-badge`) — визуал не меняется, меняется только его `onclick`.
- Остальные 8 панелей ТЕОРИИ — без изменений в рендере и поведении.

### Побочный эффект на существующие тесты

`tests/unit/test_saylor_series_section.py::test_render_saylor_series_section_builds_index_and_episode_panels` сейчас проверяет, что **после одного вызова** `renderSaylorSeriesSection()` в DOM сразу есть и индекс-карточка, и полная панель эпизода (`id="saylor-series-01"`) с телом пунктов. После этой правки это перестанет быть так — полная панель появляется только после клика/`showSaylorEpisode()`. Тест переписывается на новую модель: отдельно проверяет, что после `renderSaylorSeriesSection()` есть индекс без полных панелей, отдельно — что `showSaylorEpisode(id)` рендерит панель по требованию.

## Тестирование

- `renderTOC()`: плоский вызов даёт прежний набор данных без `group`-заголовков (регрессия на `macrocontext-toc`/`lightning-toc` — не должны сломаться); сгруппированный вызов даёт секции с заголовками групп, сумма items корректна в счётчике.
- Saylor Series: `renderSaylorSeriesSection()` без клика не создаёт полных панелей эпизодов (0 совпадений `renderAccItem`-контента в DOM); `showSaylorEpisode(id)` рендерит ровно один эпизод; `showSaylorSeriesIndex()` возвращает к сетке, не оставляя старую панель эпизода в DOM (не двойной рендер); `related_episodes`-бейдж на ещё не показанный эпизод триггерит его рендер перед скроллом.
- Существующий `test_render_saylor_series_section_builds_index_and_episode_panels` переписывается под новую модель (см. выше), не удаляется молча.

## Объём этой сессии

Реализуется целиком за один заход (не по эпизодам, как контентная работа) — это инфраструктурная правка, затрагивающая уже написанный код, а не постепенно поступающий пользовательский материал. Группировка `theory-toc` фиксирована сейчас по таблице выше; при появлении новых панелей ТЕОРИИ в будущем — решение о группе принимается точечно, не автоматически.
