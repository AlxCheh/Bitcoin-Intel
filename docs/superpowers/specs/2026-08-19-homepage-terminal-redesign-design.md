# Редизайн ОБЗОРА под терминал (Bloomberg/Arkham) — дизайн

**Дата:** 2026-08-19
**Статус:** черновик, ожидает ревью пользователя
**Скоуп:** только вкладка ОБЗОР (`#tab-home` в `index.html`) и её JS-рендер в `js/app-main.js`. Другие вкладки, схема сигналов, механизм синтеза (`ALGORITHM.md`) не затрагиваются.

## Контекст и мотивация

В этой же сессии на сайт добавлен блок «Философия проекта» (`docs/superpowers/specs/` — коммит `b579718`), формулирующий Bitcoin Intel как личный intelligence-терминал автора: не медиа, каждый вывод прослеживается до сигнала, без прогноза цены и TA. При ревизии ОБЗОРА на соответствие этой философии найдено два расхождения:

1. `#dash-definition` наверху ОБЗОРА — продуктовый питч третьим лицом («платформа... показывает где правда ещё не решена»), конфликтующий по тону с манифестом внизу той же страницы.
2. Сама вёрстка ОБЗОРА (карточки сплошной прозой) архитектурно ближе к ленте блога, чем к терминалу — Bloomberg/Arkham используют плотные панели с полями, таблицами и минимумом прозы.

Пользователь подтвердил направление: превратить ОБЗОР в дашборд в терминальной эстетике, отталкиваясь от уже принятого дизайн-языка сайта (тёмная тема, `--btc` золотая рамка, `panel-head`, IBM Plex Mono/Sans). Решения ниже провалидированы визуальными мокапами на реальных данных `signals.json`/`synthesis_cache.json`/`ENTITIES.json` в ходе брейншторминга.

## 1. `#dash-definition` → нейтральная статус-строка

Убрать продуктовую формулировку. Заменить на короткую техническую строку без маркетингового тона (в духе того, что уже пишет `dash-status-bar` рядом) — например тип и охват данных, без самоописания сайта как «платформы». Точная формулировка — на усмотрение реализации, требование: не переопределять смысл сайта (это теперь исключительно роль блока «Философия проекта»), не звучать как питч для внешнего посетителя.

## 2. Новый компонент карточки нарратива

Заменяет текущий формат (только `tension` + `macro_implication` прозой) во всех местах, где рендерится карточка кластера на ОБЗОРЕ (сейчас это `dash-narratives-list` и `dash-narratives-mini-list` — с этим редизайном они объединяются в одну ленту, см. §3).

**Структура карточки (сверху вниз):**

| Блок | Источник данных | Примечание |
|---|---|---|
| Заголовок | `cluster` → `CLUSTER_LABELS[cluster]`, флаг фазы (напр. «АКТИВНЫЙ КОНФЛИКТ» при `phase==='active'` в `synthesis_cache.json`), счётчик сигналов, точка `dir` | dir точки в заголовке — по `dir` анкорного сигнала (не путать с watchlist, §4 — там агрегат) |
| Строка полей | `DIR / HORIZON / WEIGHT / ROLE / ACTOR` анкорного сигнала (`synthesis_cache[cluster].anchor_signal_id` → найти в уже загруженном `SIGNALS` по `id`) | 5-колоночная плотная сетка, как security-header в Bloomberg |
| Tension | `synthesis_cache[cluster].tension` | Golden-цитата, стиль без изменений (левая рамка `--btc`) |
| Macro | `synthesis_cache[cluster].narrative` (macro_implication) | Проза, без изменений по содержанию |
| Чипы связей | `links.confirms/contradicts/context_chain` анкорного сигнала, счётчики | Показывать только непустые типы связи |
| Теги сущностей | `ENTITIES.json`, записи где `signal_refs` содержит `anchor_signal_id` | Опустить блок, если сущностей нет |
| Футер | `source` анкорного сигнала слева; ссылка «Все N сигналов кластера →» справа | N — реальный счёт по `signals.json` (см. §5, не устаревший `signal_count` из кеша синтеза) |

Все поля берутся из уже загруженных на клиенте структур (`SIGNALS`, `ENTITIES`, `synthesis_cache.json` уже фетчится для нарративов) — новых сетевых запросов не требуется.

## 3. Лента карточек — расширение отбора

Текущая логика отбора кластеров в ленту (`js/app-main.js`, функция вокруг `scoreCluster`/`SCORE_MIN`/`MAX_SHOWN`, строки ~2562–2618) остаётся, меняется только константа:

```
MAX_SHOWN: 4 → 8
```

`SCORE_MIN` (порог 10) не трогаем в рамках этого редизайна. При реализации проверить эмпирически на текущем корпусе, сколько кластеров реально проходит порог — если заметно меньше 8, это отдельный, самостоятельный вопрос (менять ли порог), не решается этой спекой заранее вслепую.

Прежнее разделение «Главная история» (1 карточка прозой) + «ещё нарративы» (компактный список остальных) **упраздняется** — вся лента становится однородной чередой подробных карточек (§2), отсортированных так же, как сейчас (`scored`, по убыванию `score.total`).

## 4. Раскладка

**Desktop (широкий экран, ориентировочный брейкпоинт 960px):** 2 колонки.
- Левая (~68%): лента карточек §2/§3.
- Правая (~32%), сверху вниз:
  1. «Общий фон» — без изменений (уже существующий блок).
  2. Watchlist — все кластеры (на момент написания — 13, число не хардкодится), не только показанные в ленте, см. §5.
  3. «Исследовать глубже» — компактный список вместо текущих плиток (та же навигация, теснее).
  4. «Философия проекта» — свёрнута до 1–2 строк тизера со ссылкой «развернуть →» (полный текст — по клику/раскрытию).

**Mobile (< 960px):** одна колонка, тот же порядок блоков друг под другом (статус-бар → лента → Общий фон → Watchlist → Исследовать глубже → Философия). «Философия проекта» на мобильном остаётся **полным текстом**, не свёрнутым — сворачивание нужно только чтобы не «съедать» первый экран рядом с лентой на десктопе, на мобильном блок и так последний в скролле.

## 5. Watchlist — реальное соотношение pos/neg/neu

Строка на кластер: эмодзи+короткая метка (`DIGEST_CLUSTER_LABELS`), мини-полоса из 3 сегментов (pos/neg/neu, зелёный/красный/серый) и счётчик сигналов.

**Расчёт — не по анкорному сигналу, а агрегат по всем сигналам кластера:**

```js
// на клиенте, из уже загруженного SIGNALS
const counts = {}; // { [cluster]: {pos, neg, neu} }
SIGNALS.forEach(s => {
  if (!s.cluster) return;
  (counts[s.cluster] ??= {pos:0, neg:0, neu:0})[s.dir]++;
});
```

Счётчик сигналов кластера в watchlist и в футере карточки (§2) — длина реального среза `SIGNALS.filter(s => s.cluster === key)`, не `signal_count` из `synthesis_cache.json` (тот — снэпшот на момент последнего пересчёта нарративов и может отставать на несколько сигналов, см. находку в ходе брейншторминга: на момент проверки ETF/Strategy разошлись на 3–5 сигналов).

Сортировка watchlist — тем же порядком, что лента (по `score.total` из §3), так что верхние строки watchlist всегда соответствуют карточкам в ленте выше них.

## Вне скоупа

- Другие вкладки (ДАЙДЖЕСТ, МЕТРИКИ, ПУЛЫ и т.д.) — не трогаются.
- Схема `signals.json`, алгоритм синтеза, `ALGORITHM.md` — не меняются; редизайн только читает уже посчитанные поля.
- Точный брейкпоинт (960px) и итоговая формулировка нейтральной статус-строки (§1) — детали реализации, не блокируют согласование этой спеки.
